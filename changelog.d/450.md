section: New features
- [user] `vetinari init` in a project whose `origin` is on github.com (`git@github.com:` or `https://github.com/`) now writes a `vetinari/config.mts` that spreads `...githubTracker()` instead of a `TODO` `fetchTask` stub and commented-out resolvers; any other `origin` (none, an SSH host alias, GitHub Enterprise, another host) still gets the skeleton, and `init --dry-run` says which config it would write and why. An existing config is still never touched (#450).
