section: Improvements
- [ops] Sandcastle never writes host-side git config — its `safe.directory`, `user.name` and `user.email` writes all run inside the container — so a project's `hostEnv: { GIT_CONFIG_GLOBAL: … }` is unnecessary: remove it. While it stays, the file it points at must `[include]` your real global git config, or host-side git (the fetch before worktree creation) loses your credential helper and prompts. vetinari's own config and the jjforge example no longer set it, and the `hostEnv` docs no longer claim it is needed (#469).
