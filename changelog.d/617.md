section: New features
- [ops] A gate can be flagged `perMerge: true` (#617). Integration then runs it on the base after each wave member's merge. A red check undoes only that member's merge (with `git reset --keep`, so local edits in the checkout survive), keeps the members already merged, and retries the member once like a merge conflict, with a prompt that names the gate, its output tail and the base commit. A second failure parks it `conflict`, asking `Merge of <branch> fails <gate> — fix it on the base, then redrive.` A co-wave build break, such as a redeclared identifier or a stale caller of a changed signature, is pinned on the member that caused it instead of parking the whole wave `red-base`. The `re-admit` event gains `gate` and `detail`, and the dashboard reads `#<id> retrying failed check — <gate>`. Config load rejects a non-boolean `perMerge`.
